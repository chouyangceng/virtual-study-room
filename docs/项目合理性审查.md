# 虚拟自习室项目合理性审查

日期：2026-08-09

这份记录不是功能说明，而是对整个项目结构、数据流和后续演进方式的审查。目标很简单：让这个项目继续长大时，不至于越来越乱。

## 结论

整体方向是合理的。这个项目已经从“单纯番茄钟”进化成了一个静态端的学习操作台，核心功能之间也能互相联动：

- 任务、计划、学科、课表、复盘、统计、目标是闭环的
- 纯前端 + `localStorage` 适合个人学习场景
- 导入、导出、同步都有了，数据不会被单一功能锁死

但它也已经进入了一个新阶段：功能很多，边界开始变薄。如果继续只加功能、不收口，后面最容易出问题的是数据一致性和用户理解成本。

## 目前最合理的地方

1. 以 `localStorage` 为主的数据模型很适合个人学习工具，部署简单，离线可用。
2. 学习日按早上 7 点切分，这个规则对长期坚持场景是合理的。
3. 计划导入、课表导入、学科导入都在向“结构化输入”靠拢，不再只是手工待办。
4. 任务和专注记录已经形成闭环：做什么、做了多久、做得怎么样，都能回头看。

## 当前不够稳的地方

1. 数据种类太多，但没有统一版本号。
   现在导出是一个 JSON 拼合包，能用，但对未来迁移不友好。

2. 任务、计划、学科、课表之间有少量概念重叠。
   比如“学科”既是统计维度，也是任务归属；“计划”既能生成任务，也能单独管理。现在还能跑，但以后要保持字段命名更克制。

3. 同步与备份缺少明确的兼容边界。
   以前的文件能导入，是因为字段大多还没变太狠；但这不能当作长期策略。

4. 功能已经比较多，入口一多就容易“找不到在哪”。
   所以后续更应该做信息组织，而不是继续堆按钮。

5. 单文件版必须和模块版保持同一条模块链。
   一旦 `import-hub`、`sync`、`reviews`、`stats` 这种“主链模块”缺失，导入、备份、复盘、统计就会断。

## 已经做出的修正

1. 导出备份增加了 `schemaVersion`。
2. 导入时会识别备份版本；如果以后出现更高版本，会先提示用户再继续。
3. 多级分类和标签已经进入任务与模板体系，信息结构比之前更清楚。
4. 单文件版已补齐 `import-hub`、`sync`、`reviews`、`stats` 等核心模块，保持与源码版一致。

## 后续建议

1. 给所有导入/导出文件维持统一版本号和迁移说明。
2. 继续收敛“计划”和“任务”的边界：计划负责结构，任务负责当天执行。
3. 给标签增加治理能力，比如同义词合并、常用标签置顶、废弃标签清理。
4. 统计优先围绕学习决策来做，不要为了好看而加图表。
5. 保留一个“系统说明页”或“维护页”，把数据键、版本号、兼容规则放进去。

## 一句话判断

这个项目的方向是对的，但下一阶段最重要的不再是“再加一个功能”，而是“让所有功能都能解释得通、接得上、改得动”。
